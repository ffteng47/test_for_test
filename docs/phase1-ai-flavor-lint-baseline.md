## 0 口径与调用面（先把「喂什么、怎么喂」钉住）

- **正文唯一口径** = `plot_engine.reading.read_run(Path("sampling/<run>"))` → `chapters[i]["text"]`（`## Draft` 段、已剥 HTML 注释）。**不自己抠 markdown**：E12/E19 两次都是自家解析器取段范围写窄导致少算，这次不第三次。
- **规则调用** = `from plot_engine import ai_flavor_lint` → `scan_document(mask_style_text(text, load_style_whitelist(dump_path)))`，即 `scan_file` 的语义按文本版重放（import 调用，240 章不起 240 个进程）。`review`/`calibration` 字段用交付物自己的 `REVIEW_CLASSES`/`CALIBRATION` 登记表补齐。
- **交付物的接口事实**（读码所得，未改）：`scan_document(text)` 返回 `{line, column, type, severity, message, excerpt}`，**不含** `review`/`calibration`（只有 `scan_file` 补）；CLI 有 `--json` / `--list-review-classes` / 空操作的 `--check`；**`--fail-on` 不存在**（传了走「Unknown option」返回 2）——交付说明里「门控已移除」与代码一致，所以本层不引入任何 gate。
- **书目级豁免**：`load_style_whitelist` 只读「本书目录」下的 `.deslop-whitelist`。全仓库**没有任何 `.deslop-whitelist`**（实测：本层该步是恒等变换）。豁免机制存在但从未被行使，本语料的读数里没有它的作用。
- **语料范围**：`sampling/*/dump` 存在的全部 **24 个跑法 / 240 章次**。
- **唯一一处不经 `read_run` 的取数**：`required_events` 不在 `read_run` 返回里，按 E15 的纪律**逐跑读 `dump/chNN.md` 第 4 行**，只取这一个字段，不碰正文。

## §3 与用户交付声称的出入（直说）

1. **「A 类 blocking ×7 在真人语料零命中或极低命中」不能外推到本项目语料。** 实测：`em-dash` 章命中 **74.3%**（484 条 / 1.88 条每千字）、`not-is-comparison` 10.4%、`trailer-ending` 4.8%。真人侧的原始声称**本层无法复核**（任务范围只允许 `sampling/*/dump`，未引入仓库外语料），但「因为真人语料零命中，所以可以当 blocking」这条推理在本题材**不成立**：`em-dash` 在这里是常态排版，逐处命中即满盘。
2. **「七条 A 类可以替人眼看 R1/R4/R5」——实测替到的只有 `long-paragraph` 对 R5 段长项的一半。** `period-stutter` 全库 0 命中（门比语料上界高 3 倍），`negation-parade`/`reverse-not-is`/`voice-contrast` 各 1 章，`trailer-summary` 0 章；R4 的人眼活在 canon 正文里根本没有对象（非叙事文本 = 0/230）；R1 是信息层重复，词面句式规则量不到。
3. **「新维度可能和判定面重叠」——本语料里这个重叠是辛普森假象。** 原始口径看 `stock-reaction-tic` 判死−首轮 +21.5pp 像「尺已经看见了」，族内标准化后只剩 +4.0pp，且族内命中池的过线率反而**更高**（+11.4pp）。⇒ 集成时的硬约束是：**任何这类跨臂并列必须同族内做**，否则会把「模型差」读成「质量差」（E4/E11 的同一条教训，换了面复发）。
4. **「INFERS 必需章 = ch01/ch05/ch09/ch10」——ch10 不含 INFERS。** 实测 23 个有正文跑法逐字一致：INFERS 只在 ch01、ch05、ch09（各 23 章次），ch10 的 `required_events=['OBSERVES']`。
5. 一处口径提醒：本任务的「命中率/240」列按任务口径给，但**有效分母是 230**。10 个空正文章不应当成「230 条零命中证据」，也不应当成「规则没抓到的失败章」。

## §5 为什么先实测、再集成（勘误账的三条教训直接适用）

- **E12/E19（自家解析器取段范围写窄 ⇒ 少算）**：本层把取料完全交给 `read_run`/`metrics_from_dump`（sample/viewer 同一条路），只在 `required_events` 这一个字段上按 E15 的纪律读 dump 第 4 行。若像前两次那样自己 `re.search` 抓第一个 `## Proposals`/段，密度换算的分母就会错，而错法是**静默的**。
