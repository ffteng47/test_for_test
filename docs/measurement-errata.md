# 读数勘误账（measurement errata）

**为什么要这份文档**：Phase 0/1 到今天为止，几乎所有「结论翻车」都不是判断错，是**读数转录错**——
把日志里的人话抄进表格、把累计量当瞬时量、把跨端点的数并进同端点的表。这类错单条看无害，
合起来足以把主力模型的裁定推向反方向（E4/E11 就差点做到）。所以每一条都记在这里，
并写明**现在哪段代码或哪条纪律拦住了它**——没有防线的条目就是待办。

用法：写基线/对照文档前，先扫一遍这张表；发现自己正要犯其中一型，就把该型防线走一遍。
新错按 E<序号> 追加，不合并、不改写历史（历史是证据）。

## 三、写基线文档的固定动作（把上面这些变成流程）

1. **数字一律来自 `readout`**，不来自肉眼读日志：
   `python -m plot_engine.readout sampling/<a> sampling/<b> …`（判据列＋归因列＋文笔列），
   `--matrix` 出逐章终态。**直接粘贴，不重排、不改列名**。
2. 每个数字旁边写**来源**（哪个目录、哪条命令），跨端点的读数另起一节并标「复现核对」。
3. 三件事必须显式声明，缺一条就不落笔：**累计 vs 终值**、**范围 vs 点值**、**配置差异全表**。
4. 落档前跑一次**对抗核数**：把文档丢给一个只读 agent，要求「只报不一致，不报通过项」。
   本轮这一条抓出 6 处（E5–E10），成本是一次 subagent 调用。
5. 发现自己正在犯表里某一型 ⇒ 当场在文档里写「本文初稿的 X 是错的，已改」，
   并在这张表加一行。**自我更正是档案的一部分，不是污点**（E2/E11 都靠这个才没往下 propagate）。
