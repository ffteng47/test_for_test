## 1. 这个实验回答的是什么问题

一句话：**「把本章必须发生的跃迁告诉写手」是产品配置，还是协议变更？**

Phase 0 的三次采样测的是**盲写配置**：写手拿到的只有场景目的、节拍 `intent` 文本和一份可用事实清单
（`llm_writer.py:37-51`），本章的 `must_change` 目标与 `required_events` 类型**从不进提示词**，
只用来事后当尺子。三个稳定失败章（ch02 / ch07 / ch10）全部能归到「模型在猜」，五个抖动章同理。

盲写配置的使命（压力测试校验层，证明尺子判得对）已经完成，且已完成到可以退役的程度。
本实验把「告知」当作产品配置来测，而不是当作补丁来打。

## 2. 冻结边界：尺子冻，配置不冻

- 引擎继续冻在 `f99cc00`。validator / reducer / commit / 分类表是**尺子**，本实验一律不动。
- `llm_writer.py` 的提示词模板是**产品配置**，从冻结面剥离，独立版本化：模板常量加 `PROMPT_VERSION`，
  每次采样把当轮版本写进 `run.log` 与报告表头（`prompt_version=v0-blind` / `v1-told`）。
- 这样 A/B 只是配置变体，**不构成重新冻结**，也不需要「重采三次作废历史」。
  纪律落成一句话：**尺子慢变、配置快迭代**。

## 3. 红线（预注册，不可在跑完后调整）

1. **答案键不进提示词**：`knowledge_forbidden` 的 fact、本章尚未揭示的 fact、`expected_value` 之外的状态秘密，
   一律不给。告知型模板只给两样——`must_change` 的 `(actor, field, target_fact, 目标状态)` 与
   `required_events` 的事件类型清单。给的是「作者大纲」，不是「答题卡」。
   理由：一旦把 forbidden 清单喂进去，H5.6/H5.7 的通过率就不再是模型行为，而是提示词代劳，
   整把尺子失效。
2. **不改解码参数**：温度、`max_tokens`、`extra_body` 与 `docs/phase0-batch6-model-plan.md` §1 逐字一致；
   模型仍是 `qwen2.5:14b`（`router_local.json` sha12 `a820beb0d944`）。唯一变量是提示词。
3. **不加 seed**：与 v2 三次同为独立抽样，方差口径不变。

## 4. 指标与决策规则（预注册）

| 指标 | 定义 | v2 盲写基线 | 告知型判据 |
|---|---|---|---|
| **主指标：首轮通过率** | 第 0 轮即提交的章数 / 生成章数 | 40% / 30% / 30% | 三次均 **≥ 90%** |
| 次指标：最终提交率 | `chapters_committed / chapters_generated` | 60% / 40% / 30% | 用于 E2（判据 70%），三次均须过 |
| 成本：token / 章 | `run.log` 的 tokens ÷ 生成章数 | 3955 / 4672 / 5005 | 只呈现，不设闸 |
| 防线 1：H5.7 泄漏率 | 最终判定含 H5.7 的章数 / 章数 | **0/30 章**（轮次级 1 次） | **不得高于基线**，一条即查 |
| 防线 2：人工文本质量抽检 | 每变体随机抽 3 章，按「是否成文、是否为达标而写成清单体」判 | 无（v2 未做） | 3 章中 ≥2 章成文；塌了即判**机械服从** |

**决策规则**（跑完直接按表落，不做事后解释）：
- 主指标三次 ≥90% 且两道防线均未破 → 产品形态定为**告知型 writer**，Phase 1 按该形态立项。
- 主指标达标但防线破 → 判为**机械服从**，告知型不算通过，报告写明「分数好看不等于引擎变好」。
- 主指标不达标 → 告知不是瓶颈，回到 backlog #8（seed / 低温 / 更强模型）继续找。

**三次一致性口径沿用 v2 的预注册铁律**：主口径三次不一致时呈现三次完整并列，禁止取多数 / 合并 / 挑最好看的一次。

2. **`PROMPT_VERSION` 落地**（配置剥离，不动尺子）+ 报告表头写入版本号。
   本实验的身份标识，缺它两份读数无法区分是变体还是重冻结。

若评审要求盲写侧也在新码上复测，则总计 6 次采样、约 2 小时。

## 6. 盲写配置的退役方式：从负担改成金丝雀

用户的原话是「每次引擎改动后跑一次盲写离线夹具，通过率显著上升 = 尺子被悄悄放松」。
按现有夹具，这条要拆成两半才成立，否则哨兵不响：

- **下界哨兵**：离线盲写夹具必须保持 10/10 全绿。跌破 = 尺子被**拧严**或被改坏。这条现在就有（全量测试即覆盖）。
- **防松哨兵**：盲写夹具的通过率是个常数 100%，它不会「上升」，所以它抓不到放松。
  真正能抓放松的是**带缺陷注入的离线通过率**：`--defect` 已有 `leak|dead|no_obs` 三种注入，
  钉死「注入 N 个缺陷 → 恰好失败 N 章」的读数；尺子一旦放松，这些章会开始侥幸通过，哨兵立刻响。
  这条只写测试，不加产品代码。

## 7. 与 08 §8 退出条件的关系（重要：不改判据）

本实验**不修改** E1–E6 的任何判据——那是冻结协议 `alexandria-spec-v0.2/` 的文本，动它就是改尺子。
改的是**「E2 该在哪种配置上判」**：v2 三次证明 E2 不过的账有一大半记在一个从未被决策过的设计轴
（写手是否被告知）上，而不是引擎缺陷上。因此 Phase 1 进入标准建议表述为：

> 在**告知型产品配置**下 E2 通过（≥70% 提交率，三次一致）；盲写配置的 E2=False 留档为校验层压力测试基线。

这是实验配置选择，不是协议变更；措辞上请避免写成「把 E2 的阈值改了」——那才是越权。
