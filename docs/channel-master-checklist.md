# 渠道版母带上架对照清单（Author's Republic / ACX 规格家族）

对应 `docs/monetization-wiki.html` §2–§3。第二轮探索已把发行降级为**给客户的交付选项**，所以本清单的实际用途是：
**当客户要发海外零售端时，我们的母带要不要再加工一道、加哪几道。**

实测来源：`backend/master_audio.py`、`docs/price-list.md` 验收口径。调研日期 2026-10-10。

> **本清单写就时后期还是一个手动跑的独立脚本；现在它已接入导出链路**（安装器 `deploy/patches/add_export_loudnorm.py` 挂进 `merge_audio` / `merge_m4b`，导出即归一并落 `delivery_report.json`）。阈值与默认判据一字未改，所以下面的对照仍然成立；只是「渠道 profile」要加的地方，从 CLI 变成了同一份真源里的一个参数组。

## 0. 一句话结论

**当前交付口径与渠道规格有 4 项硬冲突（码率 / 声道 / 真峰值 / 响度）+ 1 项结构性冲突（分卷）+ 2 项缺失（底噪检测、首尾静默）。**

**响度这项判了两次，第二次才算数（2026-10-11 在我方母带上直测）**：先按 7 本商用有声书标定出 LUFS−RMS = +3.55，据此以为现行 −16 LUFS ≈ −19.6 dB RMS 在窗内；**我方母带实测差值只有 +0.65，−16.0 LUFS 对应 −16.65 dB RMS，超渠道天花板 −18 达 1.35 dB**。换算先验不可跨来源使用，渠道版要按 RMS 自己定目标。见 §2.2。

好消息：这 4 项仍然全是**导出参数问题，不是制作问题**——音频内容本身不用重跑，`master_audio.py` 加一个 profile 重过一遍后期即可（含响度这项，改的是 `TARGET_I`），成本约每本几十分钟 CPU 时间。

## 1. 渠道硬指标 vs 本项目现状

Author's Republic 与 ACX 属同一规格家族。AR 帮助文档《Audio Requirements List》列的硬项：
`MP3 / CBR / ≥192 kbps / 44.1 kHz / 底噪 ≤ −60 dB RMS / 单文件 ≤ 170 MB`；
《Audio Standards for Audiobook Recording》另加 `每轨 RMS 落在 −23 dB ～ −18 dB 之间`。

| # | 项 | 渠道要求 | 本项目现状 | 判定 | 动作 |
|---|---|---|---|---|---|
| 1 | 容器格式 | MP3（分轨上传，非单一整书） | `merge_m4b` 产 M4B + 一个「MP3 合并版」 | ⚠️ 半合格 | 必须产**分段 MP3**，M4B 只作自用母带 |
| 2 | 码率 | ≥192 kbps **CBR** | `libmp3lame -b:a 128k` | ❌ **不达标** | 改 `-b:a 192k`；禁止 `-q`/`-V`（会变 VBR 直接拒） |
| 3 | 采样率 | 44.1 kHz | `SAMPLE_RATE = 44100` | ✅ 合格 | — |
| 4 | 声道 | 单声道 mono | 代码里**没有 `-ac 1`**，跟随输入 | ❌ 未保证 | 显式加 `-ac 1`（语音立体声只会让体积翻倍） |
| 5 | 响度 | **−23 ～ −18 dB RMS** | 母带实测 **−16.65 dB RMS**（= −16.0 LUFS） | ❌ **超天花板 1.35 dB** | 见 §2.2：LUFS 换算先验在我方母带上不成立，渠道 profile 需按 RMS 直接把 `TARGET_I` 降到约 −19.6 |
| 6 | 峰值 | ≤ **−3 dBFS** peak | `TARGET_TP = −1.5 dBTP`；实测输出 −2.16 dBTP | ❌ 超 0.84 dB | 渠道 profile 的 TP 目标收到 −3.5～−4.0（留 alimiter/ISP 余量） |
| 7 | 底噪 | ≤ −60 dB RMS noise floor | **完全未检测** | ❌ 缺项 | 加实测；见 §3 命令 |
| 8 | 单文件体积 | ≤ 170 MB | 整书一个文件（100 万字 = 66 h） | ❌ 严重超 | 见 §4 分卷计算 |
| 9 | 章节标记 | 需与分卷对齐 | `merge_m4b` 有 259 章标记，MP3 侧未验 | ⚠️ 待验 | 分段后每段自带章内偏移；实测 ID3 CHAP 兼容性 |
| 10 | 首尾静默 | 文件头 ≈0.5 s、尾 ≈1.0 s 静音（家族惯例） | 未定义 | ⚠️ 待验 | 分段时补 `adelay` / `apad` |
| 11 | 朗读形态声明 | **必须声明 AI/合成语音** | `price-list.md` 交付物 5 已有「AI 朗读声明文件」 | ✅ 已覆盖 | 上架表单如实填，不填是封号级 |
| 12 | 封面 | 正方形 JPG，建议 ≥1600×1600 | 流水线有 `m4b_cover.jpg` | ⚠️ 待验 | 核分辨率与文字可读性（缩略图尺寸下书名要能看清） |

## 2. 量纲坑：LUFS ≠ dB RMS（第 5 项）—— **已实测标定**

这不是参数没调对，是**两套互不等价的度量**：

- 渠道的 `RMS −23～−18 dB` = 宽带、非门控的波形 RMS（ffmpeg `astats=RMS_level`）。
- `master_audio.py` 的 `I = −16 LUFS` = ITU-R BS.1770 **K 加权 + 门控**响度（ffmpeg `ebur128`）。

### 2.1 实测锚点：7 本正式出版中文有声书

本机样本目录里有真人录制的正式出版物，取每本前 300 s 同窗对测（`astats` + `ebur128`）：

| 样本 | 录制方 | RMS (dBFS) | LUFS | **差值 (LUFS − RMS)** |
|---|---|---|---|---|
| 神探迈克狐-国际学院篇-01 | 商业成品 | −16.25 | −12.8 | +3.45 |
| 神探迈克狐-国际学院篇-03 | 商业成品 | −15.74 | −12.0 | +3.74 |
| 鬼吹灯-周建龙-003 | 周建龙（头部演播） | −21.72 | −18.2 | +3.52 |
| 我的老千生涯-001 | 商业成品 | −17.37 | −14.0 | +3.37 |
| 我的老千生涯-002 | 商业成品 | −19.85 | −15.8 | +4.05 |
| 我的老千生涯-003 | 商业成品 | −18.56 | −15.0 | +3.56 |

**差值全部落在 +3.37 ～ +4.05，中位 ≈ +3.55 LU。** 方差比预期小得多，可以当换算先验用。

### 2.2 我方母带实测：换算先验**被推翻**（2026-10-11）

`projects/shuxue/audiobook.m4b`（259 章 / 1508.6 s，已过母带后期）同一窗对测：

| 项 | 实测 | 渠道判据 | 判定 |
|---|---|---|---|
| LUFS | **−16.0** | （我方口径 −16 ±1） | ✅ |
| RMS | **−16.65 dB**（段首死气裁剪后重导：−16.33 dB，静音少了、更贴天花板） | −23 ～ −18 | ❌ **超天花板 1.35 dB** |
| 差值 LUFS − RMS | **+0.65 LU** | 商用样本先验 +3.55 | 差 5 倍 |
| 采样峰值 / 真峰值 | −2.30 dBFS / −2.48 dBTP | ≤ −3 dB | ❌（已知，见 §6.1） |

**所以 §2.1 的 +3.55 不能拿来给我们的母带做换算——它只在那批真人连续演播上成立。**
上一版据此把 §1 第 5 项判成 ✅，现在按实测改回 ❌：**现行 −16 LUFS 换算不成 −19.6 dB RMS，实际是 −16.65 dB RMS，落在渠道窗口外面。**

机制未证实，两条候选：K 加权对真人低中频的增益，合成声拿不到；以及我们的段间静音是数字零，门控与非门控的差被压小。要分开只需对同一批产料双口径对测，那是 M1 机检顺带产出的数，不单独立项。

**行动**：渠道 profile 的响度目标必须**直接按 RMS 定**，不能只改 TP/码率/声道。按实测差值 +0.65 反推，要让 RMS 落到窗口中段的 −19 dB，`TARGET_I` 得降到约 **−19.6 LUFS**，比客户交付口径轻 3.6 LU。

### 2.3 顺带测出的一个反向证据（仍成立，但含义要收窄）

正式出版的中文有声书**远比 ACX 窗口响**：迈克狐 RMS −16.2 dB（超 −18 天花板）、真峰值 **+0.8 dBFS 已削顶**。说明 `−23～−18 dB RMS / ≤ −3 dB peak` 是**欧美渠道的本地惯例，不是行业物理量**。

这支撑"客户交付口径不必向渠道口径看齐"——但**不支撑**"两套口径的响度其实已经统一"。§2.2 的实测把那句话推翻了：同一份音频在两个口径下确实落在不同侧，渠道版是**真需要单独出一版**的。

### 2.4 复核命令（渠道口径实测，本机 ffmpeg 已验证可跑）

```bash
# RMS 窗口判定（渠道口径，宽带非门控）—— 取 Overall 段的 RMS level dB
ffmpeg -hide_banner -v info -i part_01.mp3 -nostats -af "astats=measure_overall=RMS_level:measure_perchannel=0" -f null - 2>&1 | grep "RMS level dB"

# 响度（与我方口径对照）
ffmpeg -hide_banner -i part_01.mp3 -nostats -af "ebur128=peak=true" -f null - 2>&1 | grep -A3 "Integrated loudness"

# 底噪判定（渠道要求 ≤ −60 dB RMS）
ffmpeg -hide_banner -v info -i part_01.mp3 -af silencedetect=noise=-60dB:d=0.5 -f null - 2>&1 | grep silence_

# 采样峰值 + 真峰值
ffmpeg -hide_banner -v info -i part_01.mp3 -nostats -af "astats=measure_overall=Peak_level:measure_perchannel=0,ebur128=peak=true" -f null - 2>&1 | grep -E "Peak level dB|Peak:"
```

注：`astats` 的 `measure_overall=1` 会打全量指标但**只输出首行**，需指定指标名（`RMS_level` / `Peak_level`）才稳定取到值——本轮实测踩过。

若我方母带实测 RMS 落在 −23～−18 之外，**才**回头调 `TARGET_I`。这是 §7 待办第 1 条。

## 3. 两种口径并存，不是二选一

| | 客户交付口径（现行） | 渠道上架口径（本清单） |
|---|---|---|
| 响度度量 | LUFS（门控 K 加权） | dB RMS（宽带非门控） |
| 响度判据 | −16 LUFS ±1.0（我方母带实测 = **−16.65 dB RMS**） | −23 ～ −18 dB RMS |
| 真峰值 | ≤ −1.5 dBTP | ≤ −3 dBFS |
| 码率 | 128k | 192k CBR |
| 声道 | 未指定 | mono |
| 产物 | 整书 M4B + 合并 MP3 + WAV 分轨 | 分段 MP3 + 章节表 |

**响度这一行没有统一**（§2.2 实测推翻上一版的换算结论）：同一份音频在客户口径下合格（−16.0 LUFS），在渠道口径下超标（−16.65 dB RMS > −18）。**需要分 profile 的是峰值、码率、声道、响度四项，加分卷共五项——即真的要出两版母带。**

**两者都要保留**：`price-list.md` 的 −16 LUFS 是已对客户承诺的验收判据，擅自改成渠道口径＝改合同。正确形态是给 `master_audio.py` 加一个可选 profile（如 `--profile acx`），默认行为一字不改。

`linear=true` 在渠道 profile 下**仍然是前提**——分卷后章节时间轴一漂，整本对不上原文。

> **但"两版母带"这个框架本身要收敛。** 对标头部厂牌的结论见 wiki §16：播放侧各平台自己做响度归一（Spotify 默认 −14 LUFS，Apple/YouTube 各有目标），渠道的 RMS 窗口是**上传闸门**而不是播放标准。所以正确形态是 **1 份高规格档案 + 1 份渠道交付包**，不为单个平台再派生第三版。

## 4. 分卷计算（第 8 项）

192 kbps CBR = 24 KB/s。**按 170 MB 上限，单段理论 ≈2.06 小时；留质检余量按 1.5 小时切。**

| 原稿字数 | 成片时长（272 字/分钟，2026-10-11 剪段首死气后实测；旧口径 252.5） | 1.5 h/段 → 分段数 |
|---|---|---|
| 5 万字 | 3.0 h | 2 |
| 10 万字 | 6.1 h | 5 |
| 30 万字 | 18.4 h | 13 |
| 100 万字 | 61 h | **41** |

**分卷必须落在章节边界上**，不能硬切。实现上就是把 `merge_m4b` 的章节表按累计时长分组，每组一次导出——不改生成环节，只改导出环节。

100 万字切 41 个文件，这个数量级还要确认 AR 单次上传的文件数上限（§7 待办第 3 条）。

## 6. 高频被拒原因（按经验概率排）

1. **真峰值超标**——`alimiter` 限采样峰值，渠道读帧间真峰值，二者恒有差；`master_audio.py` 已为此留 1 dB 余量，但渠道上限 −3 dB 更严。**这是我方唯一确定越界的一项**（母带实测 −2.16 dBTP）。
2. **RMS 越窗**——只调 LUFS 不看 RMS。本轮标定后判断：**风险低于预期**（§2.2），但仍需在我方母带上出实测值，不能只报 LUFS。
3. **VBR**——用了 `-q`/`-V` 而非 `-b:a`。
4. **底噪/静音段不达标**——AI 合成的人声底噪极低是**优势**，但段间拼接处的爆音与残留辅音尾巴会被判噪声。
5. **章节漂移**——非线性 loudnorm 或重采样改了时长，章节标记全部对不上。
6. **封面缩略图下书名不可读**。
7. 权利文件与署名口径不一致。

## 7. 渠道 profile 的参数落点

只列改动，**不动默认路径**。现状值 → 渠道值：

| `master_audio.py` 位置 | 现状 | 渠道 profile | 理由 |
|---|---|---|---|
| `TARGET_TP` | −1.5 | **−4.0** | 渠道上限 −3 dB，`alimiter` 采样峰值 vs 帧间真峰值需留 1 dB（脚本注释已实测确认） |
| mp3 分支 `-b:a` | `128k` | **`192k`** | 渠道最低 192 kbps |
| mp3 分支 | 无 `-ac` | **加 `-ac 1`** | 渠道要求 mono；立体声只会让 170 MB 上限提前一倍触发 |
| mp3 分支 | `-b:a` 已是 CBR | 保持，**禁用 `-q`/`-V`** | 一旦 VBR 直接拒 |
| 验收报告 | LUFS + dBTP | **补 RMS_level + 底噪实测** | 渠道口径要这两个数，缺了无法自证 |
| `TARGET_I` | −16.0 | **降到约 −19.6**（以 RMS 落 −19 dB 为准，边测边定） | §2.2 实测：我方母带 LUFS−RMS 只有 +0.65，不改响度就过不了渠道 RMS 闸门 |

分卷不在 `master_audio.py` 里做——它是**导出层**的事（`merge_m4b` 的章节表分组），`master_audio.py` 只管单个音频文件的后期。两者串起来是：分卷导出 → 逐段过渠道 profile → 汇总验收报告。
