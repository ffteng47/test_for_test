## 1. 背景与商业终点

**商业终点 = 双通道（用户裁决 #2）**：自产长篇 → 网文平台连载付费 **+** 有声书付费。两通道不冲突、互为放大器，因此必须接入网文平台。

由此推出硬需求：付费阅读商业节奏（黄金三章、章尾钩子、爽点密度、付费卡点）不再是可选项，而是验收标准的一部分。有声书通道沿用现有 audiobook 流水线，本路线只覆盖"接入网文平台"侧的新增需求。

**对标对象**：Oh Story（`zenstory-ai/oh-story-claudecode`，GitHub ★7.5k，13 个 Skill 的网文 Agent 包）。用户裁决 #1 已确认核实对标分析属实。其方法论核心：扫榜 → 拆文 → 商业化写作，文件系统当记忆、确定性门禁防崩，直接对齐起点/番茄/晋江/七猫/知乎盐言的付费节奏。

## 4. 六项缺陷的技术规格（需求级，非设计级）

### 4.1 爽点/情绪工程（优先级 1）

- **需求**：章节级情绪与爽点可规划、可度量、可评审。
- **规格要点**：
  - 每章产出情绪类型 + 强度标注（落台账，可追溯）；
  - 爽点密度可统计（章/卷两级视图）；
  - 章尾钩子存在性可检测（纳入评审门禁）；
  - 与现有 tension 体系对接扩展，不另起平行体系。
- **验收（需求级）**：连续 N 章可输出"情绪曲线 + 爽点分布 + 钩子命中率"报告，且每章标注可追溯至细纲承诺。
- **依赖**：与 WP-A（epoch_1 伏笔/目标设计，待终审冻结）协调台账归属，避免双写。

### 4.2 开书前置确认闸（优先级 2）

- **需求**：规划产物（设定/卷纲/前三章规划）默认停在正文生成前，显式确认后才放行。
- **规格要点**：
  - 确认动作落事件日志，可追溯、可回放；
  - 未确认状态下正文生成路径被门禁拦截（确定性拦截，非提示性）；
  - 确认后如需改规划，走修订流程而非直接覆盖。
- **验收（需求级）**：未经确认尝试进入正文生成 → 被拦截且日志含拦截原因；确认 → 放行且事件可 replay。
- **依赖**：与现有 validator 沙盒三层判定、revision 归因阶梯同层集成。

### 4.3 量化去味工作流（优先级 3）

- **需求**：从 lint 建议语升级为量化分级 + 改写预算 + 防过矫正。
- **规格要点**：
  - 6 指标分级报告（句式模板命中、破折号滥用、否定排比等）；
  - 删除/改写预算三档：15% / 25% / 35%；
  - 过矫正检测（改写后信息量/人味回撤告警）。
- **验收（需求级）**：同一正文跑三遍去味法，指标单调收敛且不过线；报告含行号、命中片段、改写方向。
- **硬约束**：`plot_engine/ai_flavor_*.py` 为他人禁区（WP-C 暂停）。本项实施**必须等该面解冻，或在禁区外另起模块**，开工前需 tff 明确路径。

### 4.4 拆文模块库（优先级 4）

- **需求**：对标书结构化拆解 → 可被写作流程直接引用的模块资产。
- **规格要点**：
  - 拆文产物有冻结 schema（角色/剧情/设定/节奏/情绪模块）；
  - 每个情节节点锚定原文位置，标注情绪类型与强度；
  - 写作流程可按书目引用模块库（引用关系可追溯）。
- **验收（需求级）**：完成至少 1 本对标书全量拆解；写作时引用模块库的章节可通过一致性检查。
- **边界**：拆文是"技法提炼"，不是情节照搬；模块库为资产，不进正文生成路径的强依赖。

### 4.5 扫榜（优先级 5）

- **需求**：平台榜单采集 + 题材/人设/切入点/爽点节奏分析 → 选题决策报告。
- **规格要点**：
  - 目标平台：起点、番茄、晋江、七猫、知乎盐言；
  - 产出：可行性、差异化定位、失败风险三段式结论；
  - 与内核解耦，独立工作包（采集层与 plot_engine 无写集交集）。
- **验收（需求级）**：输出一份可执行的选题决策报告，含数据来源与采集时间戳。
- **依赖**：网络采集能力（浏览器/CDP 或爬虫），沙盒外运行，需单独放行。

### 4.6 旧稿导入（优先级 6）

- **需求**：已发布前 N 章反向重建为可续写工程（设定/状态/伏笔/下一章承诺）。
- **规格要点**：
  - 导入产物对齐现有状态 schema（state.db + 台账）；
  - 导入后直接进入既有续写流程，无特殊分支；
  - 重建置信度可标注（高置信自动入账，低置信进人工确认队列）。
- **验收（需求级）**：导入一部外部书稿前 10 章，续写第 11 章通过一致性检查与伏笔检查。

## 5. 边界与排除

- **不推翻现有内核**：前置 Schema 强制（guided decoding）属另一路线的增量增强，与本路线不冲突、不重构底座。
- **不做全自动无人值守出书**：人机协同为默认姿态，关键节点（开书、改纲）保留人工确认。
- **短篇形态**：需要，但排入后期单独立项，不进本路线验收。
- **禁区纪律不变**：`plot_engine/ai_flavor_*.py`、`frontend/*`、`deploy/patches/*` 等禁区照旧；本路线任何工作包不得越界。
- **批次纪律不变**：生成批只走 @213 且需 tff 显式放行；尺面变更一因一批 + 尺戳 bump。
