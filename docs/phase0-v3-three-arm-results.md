**v3a1 = 定点键洞。** 模型回 `"trust_level": null`，抽取层旧的缺键检查只看「键在不在」
（`llm_extract.py:149`），null 值放行 ⇒ `reducers/knowledge.py:78` 做 `None * int`
⇒ TypeError ⇒ 进程退出，后面 6 章一个读数都没有。修复后按既有坏料语义记
`missing_payload_keys` 并丢弃该条提案。

**v3b1 = 枚举键洞，且比第一个更阴。** 模型回 `"new_narrative_truth": true`（JSON 布尔），
`reducers/world.py:115` 用 `model_copy` 写 State —— **`model_copy` 不过 pydantic 校验**，
布尔静默进 blob；崩在**下一章**提交后的 `verify_parity` → `store.load_latest` →
ValidationError。崩点离元凶隔一整章，若不看 State blob 极易误判成「模型中途失效」。
允许值取 `Fact.narrative_truth` 的 Literal，不在抽取层抄副本（副本会漂移）。

**为什么修复前后仍可同面比较**：两条崩溃路径历史上从不产生读数。
v2 六次 + v3a2/a3 共 90 章 dump 里：定点键取 null **0 次**；被接受的 3 条 REVEALS 的
`new_narrative_truth` 全部是合法枚举（非法者要么没出现、要么已经炸掉整次）。
⇒ 两个修复都只把「整次作废」变成「丢一条提案并记账」，对任何已完成读数逐条等价。

**顺带审出的潜在洞（未修，不影响本轮读数）**：`audience` 在 reducer 里是被**遍历**的
（`reducers/belief.py:65,70`，应为 id 列表），但抽取层把它列在 `_ID_VALUE_KEYS` 里当单个 id 校验
⇒ 模型给合法列表会被判 `id_value_not_id` 丢弃，给字符串则逐字符遍历写出垃圾账本条目。
九次 dump 里 STATES/LIES/HINTS 被接受的提案数 **0** ⇒ 该洞至今既没炸过也没污染过读数，
记 backlog（尺的输入面，解冻期不动）。

**为什么没有中断重跑**：终止在跑的采样进程不在本次自主模式的授权内（三次尝试均被权限层
拦下，含用户已选定「杀掉驱动」之后）。九次连续跑完 + 作废臂补跑，总启动数仍 ≤12。
补跑台账（每臂要 3 份完整读数）：臂 A 得 a2/a3 ⇒ 补 **v3a4**；臂 B 得 b2/b3（b1 作废）⇒ 补
**v3b4**；臂 C 看 c1–c3。计划总启动 = 9 + 2 = **11 ≤ 12**，在预注册上限内。
**上限是硬的**：若臂 C 也作废两次（总启动需 13），不越界补跑，直接按「C 只有 2 份读数」
报不可判并给出方差 —— 预算条款本身就是判据的一部分。
