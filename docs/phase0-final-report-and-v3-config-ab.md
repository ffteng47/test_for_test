## 6. 归因闭合

### 6.1 交付一：渲染核验——v0 从来不是盲写

v1-told ch02 实渲染（节选）：

```
节拍意图: 建立读者对 fact_000003 的认知 / OBSERVES fact_000001 / 过渡
可以使用的事实: fact_000001: 宗门内存在叛徒；fact_000003: 印章 17 为伪造品
```

- 告知块是裸 ID 但命题在上方两行、**两跳可查**，不存在空指针级信息缺口。
- **`节拍意图` 行来自 `_vocab`、两组逐字相同，本身携带事件类型 + fact ID**——场景规划器把
  答案键写进了 beats，v0-beats 同样可见。
- ⇒ 本轮 A/B 的真实对比是「beats 内嵌答案键 vs beats + 显式汇总两行」，+10pp 是汇总两行的
  边际价值。"告知 vs 不告知"本轮未作答（v3 作答，见 §10）。

### 6.3 backlog #6 定案（最终措辞）：低先验 hard gate 是测量学事实，不动输入面

ch07 不是"模型不会写 belief"（t2 ch03/ch09、t3 ch07 均写出，t3 首轮命中 `SUSPECTS fact_000004`）；
也不是"F4 承载不了怀疑"（被 t3 证伪）。ch10 同理：t3 经 READS 达成 F2 known 且要求未删——
**两条都是可达的窄路径**。

> **定案**：对低先验跃迁设 hard gate = 把方差引进 E2，这是**测量学性质**，不是夹具错误。
> **本轮不动夹具**：补中间 fact = 改 Arc 输入面，首轮率的上升不能归因于引擎（与"答案后分数变好看
> ≠ 引擎变好"同构）；降 F2 的 expected rank = 剧情退让（丢失"解禁即真相揭示"语义），否决。
> 处置 = 如实呈现方差（三次并列即方差呈现）；v3 的 9 次采样为每个低先验跃迁再贡献 3 次观测，
> 样本累积后再议是否属于需要台阶的 Arc 设计问题。

**backlog #5 定案**：writer 提示词确实渲染了 required events——以 beats `节拍意图` 的形式（类型名 +
fact ID），两组都有。ARC_CONFLICT 抖动的归因从"引擎没接线"排除，落在解码侧（temp 0.8 + 无 seed），
处置等 seed/低温对照轮。

## 10. v3 方案：纯配置三臂对照（不构成重新冻结）

### 10.1 设计裁决（2026-10-10 用户定稿）

- **砍夹具**：旧稿（`phase0-closing-report-and-v3-plan.md` §10.2）的两条夹具改动（补中间 fact / 降 expected rank）全部取消——t3 已证明两条跃迁
  是可达窄路径，改动输入面会把分数抬到不可归因的位置（§6.3 定案）。低先验章让它抖，用并列呈现方差。
- **三臂不砍**：B−A = 告知效应、C−B = persona 效应，两级可分离；两臂方案在 C 达标/不达标两种
  结局下都分不清 persona 是否白加，期望总成本反而更高。本项目已被"两组共享的混淆"咬过一轮，
  不把同类混淆再埋一次。
- **v3 不是第二次冻结**：臂 A 的 stripped beats 在 `llm_writer` **渲染层**过滤（正则抹掉`节拍意图`里的
  事件类型名与 fact/char ID），**不改 planner 生成的 beats 文本** ⇒ plan 仍带 id ⇒ validator/抽取通道
  输入不变 ⇒ 尺与输入面一字不动。persona 块与汇总行同属 writer 模板配置面。
  ⇒ v2 六次读数与 v3 九次读数**第一次同面可比**。

### 10.2 臂定义（嵌套，PROMPT_VERSION 各自落 run.log）

| 臂 | 版本标签 | 内容 |
|---|---|---|
| A | `v2-stripped` | v0 模板 + **渲染层过滤后的节拍意图**（无类型名、无 ID）——第一次真正的盲写 |
| B | `v1-told` | A 基底恢复 beats 原样（= v0 beats 渲染）+ 汇总两行（**裸 ID**：`char_000001.knowledge update fact_000001 → known`） |
| C | `v1-told+persona` | B + persona 系统规则（角色身份/立场一致性，不含答案键） |

**臂 B 定案的裁定记录（2026-10-10 晚）**：原稿把臂 B 写成「汇总两行**带命题**」，与同节硬约束自相矛盾——
t1–t3 的汇总行是裸 ID，加命题后整份 prompt 不可能逐字节一致，n=6 合并的前提当场失效。
按 §6.1 的判定（裸 ID 是「两跳可查」，不存在空指针级信息缺口），命题的边际预期小，
而字节一致是 v3 唯一免费的样本量 ⇒ **B 保持裸 ID**，命题入提示词挪进 backlog #12（v4 单变量轮）。
标签也因此沿用 `v1-told` 而非 `v1.1-told`：标签相同本身就是「同一配置」的第一道证据。

**臂作用域硬约束**：渲染层过滤器**仅作用于臂 A**；B/C 的 beats 渲染与 t1–t3 **逐字节一致**
（C 只在系统规则尾部追加一行 persona，用户消息与 B 逐字节相同）。
由此：v3-B 与 t1–t3 是同一配置的六份读数，预注册允许**合并为 n=6**（依据即下面的 golden test）。

### 10.3 采样协议与决策规则（预注册，跑完直接按表落）

**自动化 golden test（常驻 CI，`plot_engine/tests/test_prompt_arms.py`，替代一次性人工核验）**：
1. A(stripped) vs v0-beats 渲染 diff = 仅 `节拍意图` 一行；
2. v0-beats vs B(told) 渲染 diff = 仅汇总两行；

### 10.4 B−A 的解释边界（防过度声称）

**不是**"汇总行的边际"——后者已由 v2 作答（+10pp）。报告措辞按此边界写。
