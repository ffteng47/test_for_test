## 2. 计划（批次 6 照这个跑，不临场改）

- **步骤 0｜可达性核实（不改码）**
  1. `curl -s http://127.0.0.1:11434/v1/models`，确认模型列表里有 `qwen2.5:14b`；
  2. 确认 `reasoning_effort` 不引发 4xx；
  3. 任一条不满足 ⇒ 批次 6 不开跑，先解决端点，不拿半残端点出数。

- **步骤 1｜钉死一份配置**：批次 6 三次全部用 **同一份配置文件、同一个模型**（默认候选：
  `router_local.json` 的 qwen2.5:14b）。三次之间**不允许**改 model 名、`max_tokens`、`temperature`、
  `timeout_s`、`chapters`、`seed`。要改就是新一轮实验，另开一节。
- **步骤 2｜命令**（三次逐字相同，只换 dump 目录）：
  `python -m plot_engine.review --live --chapters 10 --model-config @router_local.json --dump-dir <dir_N>`
  `<dir_N>` 建议 `phase0-v2-s1/s2/s3`，落在仓库外的临时目录，不进 git。
- **步骤 3｜中途失效的处置**：`_live_run` 现在对 `LlmUnavailable` 的语义是**报告作废、不出半成品**
  （08 §10 I6，已实现）。作废的那一次重跑，但**必须在报告里写明这是第 N 次尝试**，
  不然「三次一致」会被偷偷洗成「三次里最好看的三次」。
- **步骤 4｜身份写进报告**：模型名 + 端点 + 隧道与否 + 配置文件的 sha256 + 冻结 commit 号，
  一并写进 `docs/phase0-live-run-10ch.md` 的新节（不改该文档已有内容）。
  三份 dump 目录路径也写进去，失败分类能被复核。
- **步骤 5｜判定口径不变**：结论只按「三次是否一致」下，单点不立结论；
  旧数据（`phase0-fix-1` 的 8/10、严格读法 5/10，以及 `fix-2` 残片）降为**旧尺对照**，
  因为尺子在 Phase 0 中途被 D+A 两次 alignment 修正过。

## 3. 为什么三次不换模型

三次采样要回答的唯一问题是「**引擎稳不稳**」。中途换模型 ⇒ 三次之间的差异同时可能来自模型，
那个问题就没有答案了。所以：模型是**控制变量**，不是可选旋钮；它的身份必须像冻结 commit 号一样进报告。

## 4. 什么时候才允许换模型

换模型 = **换尺子**，是另一轮实验，不与这三次的「一致性」混算：

- qwen3 在隧道里恢复可见之后，作为「推理型模型」的对照轮（现有 `router_qwen3.json` 就是为它写的）；
- deepseek-r1:32b / 更强的 30b 级模型，作为「天花板」对照轮；
- 每一轮都自带三次重复，且轮与轮之间只比**分布**，不比单点。
