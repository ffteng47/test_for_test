> **v2 重要修订（2026-10-06）**：初版把 `target-architecture.md` 的一期边界误当成永久天花板。用户已澄清：**未来是多 Worker 并发、多机部署、并接入云端 OpenAI 兼容 API**。因此本文件的性质从「裁剪/删除」改为 **「一期做简化版，但必须第一天预留好扩展接缝（seam）」**——凡属并发/多模型/多机相关项，一律「先简不删、接口锁定」。

## 0. 依据基础：`target-architecture.md` 是什么

它是**一期落地范围裁定文档**（2026-10-03 建），标题虽为"目标架构"，实为**当时确认的 MVP 边界快照**：单机 3090、SQLite、单 Worker、本地 Qwen、Vue2，§6 划一期/二期/不做。**它是阶段快照，不是永久上限。** 本审计的裁剪只对其**一期边界**负责；凡与用户已澄清的路线（多机/多 Worker/云 API）相关的项，均按 §5 的"确定路线"处理——一期简化实现 + 保留接缝，而非删除。

排期：一期仍按 4~5 周压到 **2~3 周**，但**代价从"删功能"改为"晚做重基建、先锁接口"**。

## 2. 完整保留项（不因裁剪而削弱）

以下与单机裁定无冲突，`工程落地.txt` 的**原则与做法原样采纳**：

- **投影纪律**（§2 PlannerView/WriterView/ScorerView/DebugView）：按消费者切片喂 Prompt，直接降本地 Qwen 的上下文压力。
- **LLM 边界矩阵**（§3）+ `forbidden_knowledge`：挡住 `hidden_truth` 提前泄露，与 `context_manager.py`「Story Bible 摘要 + 章节状态」装配方式天然一致。
- **Chapter Commit 两阶段事务**（§1.3 begin/stage/validate/commit/rollback）：单 Worker 下更需要「合规才演进状态」的沙盒纪律。
- **跨状态一致性校验**（§1.4 `assert_consistent`）：等价于表现层已有的 `rules.py` 模式，两边共用思路。
- **失败处理矩阵**（§6.1）尤其「Beat 错误不要用重写正文弥补」——最高价值纪律，保留。
- **Arc 阶段权重表**（§4.2）：纯本地计算，保留。
- **拒绝原因日志**（§4.4 `rejection_log`）：落盘 JSON 即可，保留。
- **模型分级**（§8.1）思想：低频角色用更强 prompt / 更多候选，高频用轻量，映射到本地 Qwen 的不同上下文预算，保留其**成本意识**。
- **影子模式 / 回归套件 / 灰度回滚**（§9）：方法论保留（`rules.py`、`asr_qc.py` 已带 `--selftest`，正好复用为回归基线）。

## 3. 与「已成熟表现层」的衔接（不重复造轮子）

代码注释已在引用一套「五层架构」，表现层确定性组件**已落地**，剧情引擎裁剪后应对齐复用、而非另起：

| 表现层现状（已落码） | 对应 `工程落地.txt` 概念 | 复用方式 |
|---|---|---|
| `backend/emotion_map.py`（instruct⇄emotion/intensity 双向量化，注释「第②层出口」） | §2 投影 / §1.1 `state_hash`（幂等） | 表现层「同情感同强度必同文本」= 渲染侧幂等，无需新建 |
| `backend/rules.py`（`unknown_speaker/emotion_jump/pause_sanity/missing_audio`，「只报警不改写」，带 selftest） | §1.4 `assert_consistent` / §5 Rule 对象 | 剧情侧规则引擎**照此模式**写；两边共享 Finding 结构 |
| `backend/asr_qc.py`（faster-whisper 逐段回听，注释「第⑤层」，err>8% 标 retry） | §6.1 失败矩阵 TTS 分支（不阻塞 State Commit，进重试队列） | 「QC 失败只重生成段落、不回退改剧情」，与既有 `--write 置 qc=retry` 语义吻合 |

## 5. 路线图触发点（多数已是确定路线，接缝须一期就位）

v2 修订后，下列**不再是"若发生再说"的假设，而是用户已确认的路线**——所以对应能力归入"一期简化实现 + 接缝锁定"，重基建按触发点接入：

- **R1（=F1，确定路线）多 Worker 并发**：C1 并发安全写路径 + C5 append-only 事件**一期必须已到位**；触发点到达时只需加"分布式队列/多进程调度"，状态层零改。
- **R2（=F3，确定路线）云端 OpenAI 兼容多路 API**：C2 的 `evaluators[]` 列表接口一期已备；接入云 API = 往列表里加一项 + 配路由/密钥，主流程不动。
- **R3（=F4，确定路线）多机富余显存 → embedding 语义去重**：C3 的 `dedupe()` 接口一期已留；换实现不改调用方。
- **R4（=F2，确定路线）多服务器机群运维 → Prometheus+Dashboard**：C4 的 trace 字段一期已按 `ChapterTrace` 锁定；上指标栈时按已锁字段映射。
- **R6（=F2，新增契约）算力/显存注册表**：多机各卡上报「显卡数 / 显存总量 / 剩余显存 / IP」（服务发现或自动注册）。这是本审计此前未覆盖的**新地基**，建议一期先定义只读契约（`ComputeNode{node_id, ip, gpus:[{vram_total, vram_free}], last_seen}` + 注册/心跳接口），调度器按 `vram_free` 路由 TTS/ASR/embedding 任务；一期单节点即该表的一行，天然前向兼容。
- **R5**：出现「正文进度与状态进度分叉」（`剧情设计方案1.1.md` §16「写了第 80 章、库还是 73 章」）→ 说明 Commit 纪律不足，优先补强事务，而非急着加并发设施。

## 7. 术语表（大白话）

- **幂等**：同一操作做 1 次和做 N 次，结果与只做 1 次完全一致，多做不会越改越乱。例：`state_hash` 让"同一章提交两次"第二次被识别为已提交直接丢弃，状态不会推进两遍。
- **量化**：把"无穷多种自由写法"压进"有限的标准档位"。例：`emotion_map.py` 把"喊/大声喊话/yell/提高声音"统一归到标准档 `(shout, 0.8)`。
- **量化幂等（合称，指 emotion_map 那类）**：自由文本 → 规范化 `(emotion, intensity)` → 一句确定 instruct；对已规范化的值再跑一遍输出不变（该文件 selftest 即断言此）。效果＝同情绪同强度全库必同文本 → 风格可控、可复现、反复重跑不漂移。
- **乐观锁 / CAS**：写状态时带上"我以为的旧版本号 `expected_version`"，只有版本对得上才写、并原子 +1；对不上说明有人抢先改过，拒绝写入、重来。适合"并发少、冲突罕见"场景。
- **WAL / append-only 事件日志**：先只追加地记日志、再改真实状态；进程崩了可靠日志重建到一致状态。日志永不删，回滚只是把指针指回上一快照。
- **接缝（seam）**：一期用简化实现、但把接口/数据结构按未来形态锁死，日后换重实现不改调用方。
- **投影（View）**：不把全书状态整坨塞进 Prompt，而是按消费者（Planner/Writer/Scorer/Debug）只切它需要的那片，省 Token 且挡住 `hidden_truth` 泄露。
